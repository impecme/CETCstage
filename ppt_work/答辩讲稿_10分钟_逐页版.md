## P03｜赛题重述（20 秒）

赛题交付的不是孤立 kernel，而是保持 CPU/GPU 一致语义的算子库。我们在 ZQ500 上完成 81 个公开算子的 GPU 执行，并跑通雷达检测、特征融合跟踪两条任务，交付正确性、性能和可追溯报告。难点同时在算子并行化、任务组合和双后端验证。

## P04｜代码架构（18 秒）

架构分为公开 API、共享语义和 CPU/ZQ500 双后端三层。右侧是 README 的真实目录树。两条任务均调用同一套接口；Task2 helper 只承担批处理与紧凑输出，不形成额外后端。

## P05｜技术路线（18 秒）

技术路线概括为“3 类公共机制、2 条应用构建、5 类组合路径”。底层解决访存复用、依赖重构和路径分派；上层构建 Task1 公开算子链与 Task2 混合特化链。下面用三个代表算子展开公共机制。

## P06｜公共机制一：访存与资源复用（38 秒）

第一类机制是访存与资源复用。Wiener 的相邻窗口重复读取 global memory；我们将输出和 halo 划为 tile，协作加载到 shared memory，再由多个输出复用。allocation、window 和 prepared 资源按 key 缓存，减少重复准备。

代表路径由 214.44 毫秒降至 3.50 毫秒，提升 61.27 倍。该数字是历史整体路径对比，不能拆为单机制收益；fast path 仍受二维奇数窗口等条件限制。

## P07｜公共机制二：并行结构重构（38 秒）

第二类机制解决递归依赖。IIR 的当前状态依赖前一状态，不能直接逐样本并行。我们将递推改写为 affine transform，再用 tile 内 scan、tile 间 scan、初态传播和并行回代分层执行。

代表 lfilter 路径由 455.17 毫秒降至 0.359 毫秒，提升 1267.88 倍，同样是历史整体路径对比。低阶长序列适用 fast path；高阶、多线和短序列仍需通用路径。

## P08｜公共机制三：形状分派与算子内 Fusion（38 秒）

第三类机制是 shape-aware 分派与算子内 fusion。Periodogram 对实输入选择 R2C FFT，避免计算负频率；再融合前后处理，减少中间写回和 launch。FFT library call 仍是独立节点。

代表路径由 72.91 毫秒降至 0.669 毫秒，提升 108.98 倍，属于历史整体路径对比。部分 CSD、spectrogram 路径受数值约束，仍保留 C2C。

## P12｜Task1：公开算子链构建（35 秒）

Task1 是雷达检测任务，六个正式步骤均由公开算子库的 GPU 实现组合完成。输入入口上传后，Device 输出直接传给下游，到验证边界才统一回传。

具体采用模板 FFT 内容复用、scale 与 transpose/shift 融合直写、CFAR row-prefix、两级 peak reduction 和 detection list 紧凑回传，减少往返、中间数据和同步开销。

## P13｜Task1：统一 L1～L6 端到端性能（30 秒）

Task1 固定模板、FFT、Hann、CFAR 与公开算子链，只改变输入规模。全曲线保持 25 倍以上；L6 CPU 为 364.8 毫秒，ZQ500 GPU 为 11.0 毫秒，加速比为 33.09 倍。

结果取 7 次运行并排除首轮 warm-up。L6 的 Expected、CPU、GPU 检测位置一致，CFAR 误差 0.276398 小于 0.5。

## P14｜Task2：批量 score-only 混合链（35 秒）

Task2 的关键是 score-only：不逐帧物化完整相关、谱图和小波张量。GPU 按 batch 驻留，生成四路 score，再完成融合、peak 和 Kalman，只在链尾输出紧凑 track。

预编译 correlate 与 spectral 路径是协同调用的任务级 helper，不是第三后端；带内和尺度归约提前完成，Kalman 跨帧状态仍有串行依赖。

## P15｜Task2：统一 L1～L6 端到端性能（30 秒）

Task2 固定 score-only 语义，只改变帧数；batch 扩大后并行度更充分。L6 CPU 为 28363.1 毫秒，ZQ500 GPU 为 27.0 毫秒，对应 1048.78 倍。

CPU/GPU peak track 一致，RMSE 为 0.477855，小于 2；特征误差小于 1e-4。对比对象仅为 CPU reference 与 ZQ500 GPU。

## P16｜正确性与运行验证（23 秒）

覆盖、性能和误差来自同一套正式 L1～L6 报告：81 个算子有性能记录，两条任务的 12 个规模点和 14 个正式步骤均通过门限。Task1 检测位置一致，Task2 轨迹与误差满足阈值。任一验证失败，结果均不导出为 PASS。

## P17｜性能优缺点与改进方向（27 秒）

优势来自邻域复用、递归转并行、频谱写回压缩和链内驻留。瓶颈主要是访存、多阶段 launch、固定开销和 Kalman 串行链。

下一步在统一规模下做单项参数对照：Tile/Halo 调 block、halo；CFAR 调 guard、reference、pfa；Task2 调 batch、shape，并以 L6 热点确定优先级。

## P18｜核心亮点（22 秒）

项目亮点不在堆叠孤立 kernel，而在三次结构重写：Tile/Halo 将重复访存转为块内复用；Affine Scan 与 R2C/Fusion 将递归和冗余频谱转为并行计算；Device-resident 与 score-only 按任务语义删除无用中间量。
