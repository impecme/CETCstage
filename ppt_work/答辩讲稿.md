## P05｜“3 + 2 + 5”技术路线

这一页概括我们的技术路线：三类公共算子机制、两条应用任务链、五类任务级路径。

第一类是全自动调优框架与形状感知分派。框架自动完成候选生成、参数搜索、正确性与 E2E 门禁、结果记录和调优缓存；再把算子、形状、dtype、layout、batch 和语义参数组成完整调优键。运行时只查表，根据规模、布局、算法参数和平台校验选择直接计算、Tile/共享内存、FFT/R2C、并行扫描或形状特化核。缓存未命中、设备不匹配、资源不足或门禁失败时，回退安全路径。

第二类是分层 Tile 与并行归约，把重复全局访存、串行 phase 累加改成块内协作、共享数据和分层归约。

第三类是 E2E 开销与执行内资源机制。每个 warmup/repeat 都独立创建输入、buffer、plan、event，完整执行 H2D、计算和 D2H；只在本轮内部复用中间 buffer 和 workspace，跨 repeat 不复用。

两条任务链分别是任务一雷达检测和任务二特征评分与跟踪。当前 L6 CPU→GPU E2E 加速比分别为 7.49 倍和 481.37 倍；这两个数字是当前 CPU→GPU 端到端口径，不是 GPU 优化前后提速率。五类路径贯穿两条任务链。

## P06｜通用机制一：全自动调优框架与形状感知分派

第一类机制是全自动调优框架与形状感知分派，解决的是“同一个算子，不同形状不应固定走同一条 GPU 路径”，也解决“不同候选参数不能依靠人工逐个试配”的问题。

我们把输入的逻辑形状、dtype、layout、batch 和语义参数组织成完整调优键；图中的 N×F、dtype、layout 只是键摘要，不是完整键。候选集合包含 Tile/共享内存、通用直接路径、FFT/R2C、并行扫描和形状特化核。

全自动调优框架在离线阶段对有限候选自动完成参数搜索、正确性门和 E2E 门测试，并把优胜配置写入调优缓存。运行时只做精确键查找和形状感知分派，不在线试跑。静态旧路径不属于形状感知分派候选，只用于离线验证和缓存未命中、设备不匹配、工作区不足或门禁失败时的安全回退。

以图中的 Lomb–Scargle 流程为例，运行时依据规模阈值、内存布局、算法参数和平台校验选择路径，再执行频率点并行计算。这个机制不改公共 API，重点是把“路径选择”从运行时试错变为离线确定。

右侧代表性结果为：端到端加速比 194.03 倍、内核加速比 195.65 倍、GPU 优化前后提速率 278%。

## P07｜通用机制二：分层 Tile、布局与归约重构

第二类机制针对重复全局访存和串行归约。

旧路径中，每个点×通道输出都要重读相同输入样本和相位 tap，phase 累加也在通道维串行完成。

新路径按点×相位组织输入 Tile，共享相位 tap Tile 和 8×8 twiddle；一次加载后，块内完成相位乘法和分层归约，并行生成多通道输出。运行时根据通道数和点数选择通用路径或 8 通道点路径，条件不满足时保留旧路径。

这相当于把重复读取和串行累加改成“Tile 协作加载、共享数据、分层归约”的 GPU 结构，减少全局访存和单线程累加路径。

右侧以 Wiener 为代表：端到端加速比 102.12 倍、内核加速比 199.70 倍、GPU 优化前后提速率 3292%。

---

## P08｜通用机制三：非内核执行开销与执行内资源复用

第三类机制针对 kernel 之外的执行开销。

每个 warmup/repeat 都有独立生命周期：重新创建输入和 template，完整执行 H2D、计算和 D2H，计时范围包含分配、plan、event、同步和结果物化。输入、device buffer、workspace、plan 和 event 不跨 repeat 复用。

在同一个 repeat 内，forward、频域计算和 inverse 阶段可以复用本轮已经创建的 packed FFT buffer、plan 和 workspace；D2H 完成后统一释放。这样减少的是单轮内部重复创建和中间数据搬运，不能通过复用旧输入或跳过 H2D/D2H 制造收益。

因此，内核时间只用于定位设备内瓶颈，算子是否有效最终看完整 E2E。右侧以 vectorstrength 为代表：端到端加速比 85.36 倍、内核加速比 106.76 倍、GPU 优化前后提速率 173%。

## P10｜任务一：设备驻留与五类路径组合雷达检测链

任务一这一页展示的是设备驻留与五类路径组合的雷达检测链。每个 warmup/repeat 都重新构造输入并完整 H2D；本轮内部才允许复用计算资源，跨 repeat 不复用。

主链在设备侧依次完成脉冲压缩、脉冲多普勒、功率图、CA-CFAR 和最终检测，链尾只回传紧凑的检测结果。模糊函数是独立的矩阵/FFT 质量分析旁路，不进入检测结果回传。

五类路径分别是：设备驻留；本轮内部的模板、FFT 和 workspace 准备；算子结果直接写入后续布局；CA-CFAR 行前缀扫描和检测归约；链尾紧凑回传。核心是让公开算子在设备端连续组合，同时保留完整的输入、计算和输出语义。

当前 L6 CPU→GPU 端到端加速比为 7.49 倍。这个数用于说明当前任务相对 CPU 的端到端结果，不代表任务 GPU 优化前后提速率。

## P12｜任务二：设备批量评分与紧凑跟踪

任务二这一页展示设备批量评分与紧凑跟踪。CPU 参考路径逐帧生成完整的相关、谱图和 CWT 中间结果，再在主机侧处理；GPU 路径一次 H2D 后采用批量 B=8，只保留后续融合需要的评分。

设备侧依次完成滤波/解调评分、相关评分、谱图频带评分、CWT 最大评分、特征融合与并行归约，再完成峰值检测、测量转换和 Kalman 紧凑输出，不物化不必要的完整二维、三维张量。

五类路径分别是：设备驻留与批处理；只计算后续需要的评分；评分结果直接进入融合布局；批量特征融合和并行归约；峰值与 Kalman 只输出紧凑跟踪结果。每个 warmup/repeat 重新输入并完整 H2D/D2H，资源复用只限本轮内部。

当前 L6 CPU→GPU 端到端加速比为 481.37 倍。这个数是当前 CPU→GPU 口径，不把它解释为任务 GPU 优化前后提速率。

## P15｜核心亮点：全自动调优与三类算子机制

这一页把前面的技术收束为一个可复用的 GPU 优化闭环，而不是三个孤立的 kernel 技巧。

第一类是全自动调优框架与形状感知分派：自动完成有限候选搜索、正确性和 E2E 门禁，运行时按完整调优键查表选路，失败时安全回退。

第二类是分层 Tile、布局与归约：把重复全局访存和串行归约改成块内协作加载、共享数据和分层归约，形成多通道并行输出。

第三类是非内核 E2E 开销与执行内资源复用：每个 warmup/repeat 独立创建并完整执行 H2D、计算和 D2H，只在本轮内部复用中间资源，跨 repeat 不复用。

三类机制分别解决路径选择、设备内计算结构和执行协议开销，最终形成可解释、可验证、可回退的 GPU 优化方法。
